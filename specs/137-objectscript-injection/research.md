# 137 Research: caller text spliced into generated ObjectScript, SQL, URLs and exec

Read-only inventory, 2026-10-17, of `crates/iris-agentic-dev-core/src`. Nothing was run against IRIS. Starting point: ee46c79 (`validate_global_name`).

## Scope and method

Every sink was checked: `execute_via_generator`, `execute` / `execute_ssh` (docker and ssh), `query(` built with `format!`, ObjectScript built with `format!`, and Atelier URLs that carry a name. For each sink the record gives where the value is placed, the escaping applied today, the write tier from `tools/write_gate.rs` `CLASSIFICATION`, and a verdict.

Verdicts:

- **SAFE**: the escaping is enough for the place the value lands. Doubled `"` inside an ObjectScript string literal is enough, as is `os_str_expr` or doubled `'` inside a SQL literal. So are a regex allowlist, a typed number, `?` binding, and urlencoding of a path segment.
- **NEEDS FIX**: the value lands in code with the wrong escaping or none. That covers backslash-escaped quotes (ObjectScript has no backslash escape), a bare splice, a SQL identifier splice, or quote stripping where a doubled `'` is needed.
- **UNSURE**: the splice is real, but whether it can be reached depends on a precondition that has not been checked.

This document does not contain working break-out inputs. It names the missing escaping, which is enough to fix each site and to write a regression test (sentinel global survives, as in ee46c79).

## Shared helpers

| Helper                                        | Where                             | Correct?                                                                                                                           |
| --------------------------------------------- | --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `os_str_expr`                                 | `objectscript.rs:16`              | Yes. Doubles `"`, emits control characters as `$CHAR(n)`, and is safe in expression position. This is the fix for most rows below. |
| `cos_str`                                     | `tools/dict.rs:380`               | Doubles `"` only. Enough in the generator, where a newline leaves an unclosed literal and the scratch class fails to compile.      |
| `os_quote`                                    | `tools/scm.rs:99`                 | Doubles `"` and turns `\n` into the literal text `$Char(10)` inside the string. The value is wrong but the call is safe.           |
| `objectscript_string_literal`                 | `telemetry/mod.rs:232`            | Doubles `"`. Params are JSON-serialized first, so no raw newlines. Safe.                                                           |
| `replace('"', "\\\"")`                        | info.rs, dict.rs, skills_tools.rs | **Wrong.** ObjectScript does not treat backslash as an escape, so the quote still ends the literal.                                |
| `validate_subscripts`, `validate_global_name` | `tools/global.rs`                 | Correct allowlists. Rust `regex` `$` anchors at end of text.                                                                       |
| `versioned_ns_url`                            | `iris/connection.rs:436`          | Urlencodes the namespace. Safe.                                                                                                    |

Execution paths: `execute_via_generator` puts each code line into a scratch class method, so a stray newline in a quoted value usually causes a compile failure, not execution. `execute` (docker exec) pipes the code to `iris session` stdin, where every line is a separate terminal command. A newline is therefore a command separator there, and quote doubling alone is not enough. Only `iris_coverage` (`coverage.rs:338-342`) and the mod.rs paths listed below fall back to docker exec.

## Ranked NEEDS FIX list

Ranked by what a caller gains. Within a tier the order is rough.

**A. Read-only tools that run caller-shaped ObjectScript or free SQL.** The write gate never fires on these.

## Gate coverage (not splices, but they decide the impact)

1. **`global_preview` and `global_kill` skip `dispatch_gate`** (mod.rs:8900, 8938). Even if they called it, gates [3] and [4] read only `global_name` / `globalName`, and these tools take `global`. So the system blocklist and the PHI name gate never run on them. `validate_global_name` accepts `%`-prefixed names.
2. **The standalone `journal_search` skips `dispatch_gate`** (mod.rs:9147). Bulk-PHI block [2] lists `journal_search`, but it fires only on the `iris_admin action=journal_search` route, so the standalone tool returns journal contents under the default `dataPolicy=block`. Verified directly.
3. **Gate [0] scans only `iris_execute`, `iris_ws_exec`, `iris_execute_method` and `iris_query`.** Every ObjectScript splice marked NEEDS FIX runs code that `check_objectscript_code_edit` and `contains_global_kill` never inspect. A splice in a write-tier tool is therefore a way past the code-edit and destructive gates, and a splice in a read-only tool is a way past the write gate as well.
4. `tool_gate!` (`tools/gate_macro.rs`) is defined but never invoked.

## Fix direction

- ObjectScript: replace every backslash-escape and bare splice with `os_str_expr`, and drop the surrounding quotes, since it emits them. Where a value is a class, routine or namespace name, add a name allowlist like `validate_global_name`.
- SQL: use `?` binding through `iris.query(sql, params, …)`, as `query_audit_log` already does. Refuse free SQL fragments (`body_where`), or send them through the same read-only validation and gate [0] SQL check that `iris_query` uses.
- URLs: urlencode `includes[]`, `category`, and the compare namespace.
- Shell: the ssh remote command must quote the namespace and container, or refuse anything outside a name allowlist.
- Gates: call `dispatch_gate` from `global_preview`, `global_kill` and `journal_search`, and have gates [3] and [4] read `global` too.
- Tests: one live test per fixed site, in the ee46c79 pattern (sentinel global set before, asserted after, writes off).
